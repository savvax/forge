# raiffeisen Integration Guide

> Generated by forge 1.0.0 from API интеграции выплат 1.0. Решения с confidence < 0.8 перечислены в разделе «Допущения».

## Кратко

- Провайдер: **raiffeisen**; спецификация API интеграции выплат 1.0 (`examples/specs/raiffeisen.yaml`).
- Сервис: `Provider::RaiffeisenService` (`raiffeisen_service.rb`) реализует контракт `Provider::BaseService`: `check_conditions`, `create_request`, `fetch_status`, `process_callback`.
- API: `https://test.ecom.raiffeisen.ru/api` (sandbox по умолчанию), production `https://e-commerce.raiffeisen.ru/api`; авторизация — Bearer token.
- Выплата создаётся `POST /payout/v1/payouts`, статус — `GET /payout/v1/payouts/{id}` и webhook `POST newPay`; итог операции — `in_progress` / `approved` / `rejected`.
- Заполнить вручную: `credentials.token`, `credentials.callback_secret`, `credentials.account`; все допущения анализа — в разделе «Допущения».

## Как платформа работает с сервисом

- `check_conditions(operation, request_method)` — предпроверки до запроса (раздел «Проверки перед отправкой»); `request_method` — тип реквизитов (`sbp`) либо служебное `status` / `check`.
- `create_request(operation, request_method)` — собирает тело по таблице «Поля запроса» и шлёт `POST /payout/v1/payouts`; успех — HTTP 200; id выплаты сохраняется в `operation.provider_operation_key` из `id`. `request_method` `status`/`check` делегируется в `fetch_status`.
- `fetch_status(operation)` — `GET /payout/v1/payouts/{id}`, статус из `status.value` по «Маппингу статусов».
- `process_callback(payload, raw_body:, headers:)` — проверяет подпись `X-Api-Signature-SHA256`, берёт статус из `payout.status`, находит операцию по `payout.id` и переводит её в approved / rejected / in_progress.
- Ошибки провайдера → `failure` по таблице «Обработка ошибок» (семантика действий — там же).

## Авторизация

- Тип: Bearer token
- Header: `Authorization: Bearer <credentials.token>`
- Хранение: `providers.credentials` (encrypted)
- Заполнить вручную: `credentials.token`, `credentials.callback_secret`, `credentials.account`

## Настройка

- ENV `RAIFFEISEN_BASE_URL` — базовый URL (default sandbox: `https://test.ecom.raiffeisen.ru/api`)
- Production: `https://e-commerce.raiffeisen.ru/api`
- `config.callback_url` — адрес приёма webhook на стороне Space Payments
- ProviderGateway config — см. раздел ниже

Все ключи, которые нужно задать до первого запроса:

| Ключ | Назначение |
|------|------------|
| ENV `RAIFFEISEN_BASE_URL` | базовый URL; по умолчанию sandbox `https://test.ecom.raiffeisen.ru/api` |
| `credentials.token` | авторизация (Bearer token), выдаёт провайдер |
| `credentials.callback_secret` | секрет подписи webhook, выдаёт провайдер |

## Сумма и валюта

- Поле `amount` (number): мажорные единицы — `operation.amount.to_f.round(2)`.
- Валюты: RUB; поле `currency`, иная валюта → `currency_not_supported`.

## Реквизиты получателя (`operation.payout_requisite`)

Тип реквизитов приходит в `request_method` и выбирает набор полей; значение для провайдера — см. «Поля запроса».

| Тип | Поля из `payout_requisite` (обязательность) |
|-----|---------------------------------------------|
| sbp | `phone` (да), `bankAlias` (да), `firstName` (нет), `middleName` (нет), `lastName` (нет), `inn` (нет) |

## Проверки перед отправкой (`check_conditions`)

Базовые проверки `Provider::BaseService` (сумма положительна, валюта и реквизиты заданы) плюс правила из схемы запроса:

| Поле | Правило | Код ошибки |
|------|---------|------------|
| currency | длина ≤ 3 | currency_too_long |
| currency | один из: RUB | currency_not_supported |
| paymentDetails | длина ≤ 140 | payment_details_too_long |
| payoutParams.phone | длина ≤ 15 | phone_too_long |
| payoutParams.bankAlias | длина ≤ 255 | bank_alias_too_long |
| payoutParams.firstName | длина ≤ 140 | first_name_too_long |
| payoutParams.middleName | длина ≤ 140 | middle_name_too_long |
| payoutParams.lastName | длина ≤ 140 | last_name_too_long |

## Маппинг статусов

| Provider | Space Payments |
|----------|----------------|
| COMPLETED | approved |
| DECLINED | rejected |
| IN_PROGRESS | in_progress |
| PENDING | in_progress |
| WAITING_CONFIRMATION | in_progress |

## Обработка ошибок

| HTTP | Provider code | Действие |
|------|---------------|----------|

Что означают действия:

- **reject** — операция отклоняется: `failure(<http>, "provider.<code>")`, платформа не повторяет запрос.
- **retry later** / **retry with backoff** — временная ошибка: `failure` с `retry_after` из `Retry-After`, если провайдер его прислал; платформа повторяет позже.
- **alert ops, block provider** — неверные учётные данные: `provider.invalid_credentials`, провайдер блокируется до вмешательства.
- **treat as success** — идемпотентный повтор (тот же `Idempotency-Key`): ответ читается как успешный.
- Сеть, таймаут, 5xx → `provider.unavailable`; 429 → `provider.rate_limit`.

## Приём webhook

- Эндпоинт провайдера: `POST newPay` (источник: top-level `webhooks` спеки).
- Адрес приёма на стороне Space Payments — `config.callback_url`; его нужно зарегистрировать у провайдера.
- Поле события: `event`; поле статуса: `payout.status`; id выплаты: `payout.id`.
- Повторная доставка того же события безопасна: переход в тот же статус идемпотентен.
- Проверка на моке: `POST /_simulate/<id>/<event>` — мок шлёт подписанный webhook на `WEBHOOK_URL`.

## Webhook signature

HMAC-SHA256(fields, callback_secret) → hex → X-Api-Signature-SHA256

Подпись считается по сырым байтам тела. Платформа передаёт в `process_callback` уже разобранный JSON, поэтому передавайте и сырое тело: `process_callback(payload, raw_body: request.body.read, headers: request.headers)`. Без `raw_body` сервис подписывает `JSON.generate(payload)` — подпись сойдётся, только если провайдер шлёт компактный JSON с тем же порядком ключей.
