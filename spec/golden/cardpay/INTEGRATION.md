# CardPay Integration Guide

> Generated by forge 1.0.0 from CardPay Transfers API 2.3.0. Решения с confidence < 0.8 перечислены в разделе «Допущения».

## Авторизация

- Тип: Bearer token
- Header: `Authorization: Bearer <credentials.token>`
- Хранение: `providers.credentials` (encrypted)
- Заполнить вручную: `credentials.token`, `credentials.callback_secret`, `credentials.merchant_id`

## Настройка

- ENV `CARDPAY_BASE_URL` — базовый URL (default sandbox: `https://api.cardpay.example/v2`)
- `config.callback_url` — адрес приёма webhook на стороне Space Payments
- ProviderGateway config — см. раздел ниже

## Методы

| Метод | Endpoint | Назначение | Idempotency |
|-------|----------|------------|-------------|
| create_payout | POST /transfers | Создание выплаты | - |
| get_status | GET /transfers/{id} | Статус | - |
| webhook | POST {$request.body#/callback_url} | Callback | X-Signature |

## Маппинг статусов

| Provider | Space Payments |
|----------|----------------|
| NEW | in_progress |
| PROCESSING | in_progress |
| SUCCESS | approved |
| DECLINED | rejected |

Не распознаны (задать в `overrides.yml` → `statuses.<STATUS>: in_progress|approved|rejected`): `ON_HOLD`

## События webhook

| Event | Space Payments |
|-------|----------------|
| transfer.settled | approved |
| transfer.declined | rejected |

## Обработка ошибок

| HTTP | Provider code | Действие |
|------|---------------|----------|
| 400 | validation_error | reject |
| 401 | unauthorized | alert ops, block provider |
| 403 | forbidden | alert ops, block provider |
| 404 | not_found | reject |
| 422 | validation_error | reject |
| 500 | internal_error | retry, alert ops |
| 503 | issuer_unavailable | retry with backoff |

## ProviderGateway config

{ "external_method": "card_payout", "gateway": "RUB_CARD_WITHDRAW" }

## Webhook signature

HMAC-SHA512(body, callback_secret) → base64 → X-Signature

## Поля запроса

| Поле | Источник | Обязательность | Преобразование |
|------|----------|----------------|----------------|
| merchant_id | `credentials.fetch('merchant_id')` | да | - |
| reference | `operation.id.to_s` | да | to_s |
| amount | `format('%.2f', operation.amount)` | да | amount |
| currency | `operation.currency` | да | - |
| description | `operation.description || "Payout #{operation.id}"` | нет | - |
| callback_url | `callback_url` | да | - |
| destination.card.pan | `operation.payout_requisite.dig('card', 'number')` | да | - |
| destination.card.holder | `operation.payout_requisite.dig('card', 'holder')` | да | - |
| destination.card.expiry | **TODO** (overrides.yml) | нет | - |

## Вне контракта

- `GET /transfers` — не используется

## Допущения

| Решение | Источник | Уровень | Как переопределить |
|---------|----------|---------|--------------------|
| no sandbox server; default BASE_URL is production (https://api.cardpay.example/v2) | production_default at `#/servers/0` | WARN | `base_url.default: <sandbox url>  (overrides.yml)` |
| status 'ON_HOLD' (on_hold) of data.state is unknown | unmapped_status | WARN | `statuses.ON_HOLD: in_progress\|approved\|rejected  (overrides.yml)` |
| X-Signature: payload not stated; raw_body assumed | signature_payload_assumed | WARN | `webhook.signature_payload: raw_body\|fields  (overrides.yml)` |
| webhook event 'transfer.on_hold' → status 'on_hold' unknown | unmapped_event | WARN | `events.transfer.on_hold: in_progress\|approved\|rejected  (overrides.yml)` |
| destination.card.expiry (string, Expiry in MM/YY format) has no source | unmapped_field | WARN | `fields.destination.card.expiry.source: "…"  (overrides.yml)` |
